# Continue development on a new server

This is a fresh development setup, not a copy of the populated public demo.
Git contains the application, built-in skills, provider examples and tests. It does
not contain accounts, databases, downloaded evidence, credentials or model weights.
The repository is private: authenticate to GitHub with your own account before cloning.

## Set up the workspace

Choose a parent directory on the new server. The commands below use the current
directory as that parent; change it first if necessary. Git and Node 24 (including
npm) must be installed. Ask before installing missing system tools. Docker, Pixi,
a GPU and the preprocessing repository are not required for this setup.

```sh
export GENESIS_WORKSPACE="$PWD/genesis"
mkdir -p "$GENESIS_WORKSPACE"/{tmp,cache/uv,cache/npm,python,bin,runtime,dev}
export TMPDIR="$GENESIS_WORKSPACE/tmp"
export UV_CACHE_DIR="$GENESIS_WORKSPACE/cache/uv"
export UV_PYTHON_INSTALL_DIR="$GENESIS_WORKSPACE/python"
export npm_config_cache="$GENESIS_WORKSPACE/cache/npm"
export PATH="$GENESIS_WORKSPACE/bin:$PATH"
```

If uv is missing, use its official installer, keeping the installation here:

```sh
curl -LsSf https://astral.sh/uv/install.sh -o "$TMPDIR/uv-install.sh"
UV_INSTALL_DIR="$GENESIS_WORKSPACE/bin" UV_NO_MODIFY_PATH=1 sh "$TMPDIR/uv-install.sh"
```

Clone and build:

```sh
git clone https://github.com/kundajelab/genesis-curation.git "$GENESIS_WORKSPACE/genesis-curation"
cd "$GENESIS_WORKSPACE/genesis-curation"
uv python install 3.14.5 --no-bin
uv sync --frozen --extra web
uv run --frozen genesis --help
node --version  # must be v24.x
(cd frontend && npm ci && npm run build)
scripts/check.sh
```

Frontend assets are generated by the build and intentionally excluded from Git.
The Python environment is local to this checkout. No global `genesis` command is
needed: use `uv run --frozen genesis` from the repository.

## Start the local GUI and worker

Use a private runtime on a local filesystem (not an SMB share). Choose a new
password of at least 14 characters; `init` prompts without printing it. It is a
one-time operation for this runtime.

```sh
export GENESIS_RUNTIME="$GENESIS_WORKSPACE/runtime/development"
export GENESIS_PROVIDERS="$GENESIS_WORKSPACE/genesis-curation/examples/curation/providers.mock.json"
uv run --frozen genesis web init --root "$GENESIS_RUNTIME" --username curator
uv run --frozen genesis metadata import --root "$GENESIS_RUNTIME" \
  --file examples/curation/synthetic-review.csv \
  --namespace "Synthetic development" --classification local-only
uv run --frozen genesis web serve --root "$GENESIS_RUNTIME" \
  --providers "$GENESIS_PROVIDERS" --origin http://127.0.0.1:18765 \
  --port 18765 --dev
```

In a second terminal, restore the same workspace/environment variables, change to
the repository, and start the worker:

```sh
uv run --frozen genesis web worker --root "$GENESIS_RUNTIME" \
  --providers "$GENESIS_PROVIDERS"
```

Both processes must remain running. For a remote server, run this on your laptop,
replacing `USER@SERVER` with your SSH login:

```sh
ssh -N -L 18765:127.0.0.1:18765 USER@SERVER
```

Open **http://127.0.0.1:18765** and log in as `curator` with your new password.
This setup binds only to loopback. Public deployment is documented separately in
[deployment](usage/deployment.md).

### Try the synthetic review

1. Open **Review**, change **Show** to **Source identity needed**, and select
   **Synthetic development**. The example has no real archive accession.
2. Click **Prepare study** using the mock provider. The worker prepares two records;
   the intentionally missing tissue should become a review question.
3. Open the question, inspect its evidence, and record an unknown value or defer it.
   Review the original/prepared values and **Change history**.
4. Sign-off remains a separate human action. Deferred questions prevent sign-off;
   explicitly marking a value unknown leaves it out of the signed metadata.

The CSV import exercises study review; it does not populate the Curation workbook
or invent discovery records. Discover and Curation start empty. The mock provider
is deterministic software test behavior, not an LLM or accuracy benchmark. Do not
use Discover during this offline example: discovery still performs real network
searches even when the model provider is mocked.

## Use real models and data

Copy a provider example into your private runtime and configure it there. See
`examples/curation/providers.live.example.json` and `deploy/web/providers.example.json`.
Use the same provider file for the server and worker, restarting both after edits.
OpenAI-compatible endpoints (including local servers) and Anthropic endpoints use
explicit configuration. Credentials stay in private files or the documented secret
references, never Git. Check configured context/input/output budgets against the
actual served model. Use `uv run --frozen genesis ai --help` for provider/model tools.

A fresh clone does not install or start model servers. GPU capacity, model licenses,
weight downloads and serving configuration are separate provisioning steps. The
demo's model-controller deployment is not a generic automatic installation for a
new server. An available provider configuration does not prove model availability
or curation accuracy. Obtain permission before downloading public sequencing data.

Discovery combines archive/literature queries, optional web search and repository
recipes. Coverage can be partial. Preserve real search receipts, imported claims,
source versions and human decisions. Never modify the original external reference
spreadsheet or label its rows as generated by this tool. See [workflow](usage/workflow.md).

## What to verify when continuing

Run `scripts/check.sh` for the offline Python checks and build the frontend with
Node 24 after UI changes. Report exact failures and NOT RUN results. Mock provider
tests do not establish biological accuracy, live archive coverage or GPU serving.
`tests/browser_demo.cjs` expects a populated demonstration workspace and is not a
fresh-install smoke test. For a fresh install, use the synthetic walkthrough above.

Keep SQLite on local disk and monitor free space; background work pauses when
storage thresholds are reached. Back up runtime state independently if needed.
Git cloning alone never migrates accounts, review history or populated tables.
